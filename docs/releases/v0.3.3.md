# Energizados v0.3.3 — Notas de versión

> Fecha de release: 2026-07-27
> Tipo: minor (nueva feature, sin breaking changes)
> PR: [#33](https://github.com/EL-BID/Energizados/pull/33)

---

## Resumen ejecutivo

Esta versión agrega **modo de entrenamiento sin holdout** (`split.method: "none"`), pensado para entrenar modelos de producción con el 100% de los datos una vez completada la evaluación offline. Es la primera capacidad nueva del framework en responder a un pedido concreto de los proyectos de campo (CELESC, entre otros).

Además, incluye una refactorización interna (ADR-0001) que mueve el clustering geográfico del ETL al transformer — un cleanup arquitectónico sin impacto en la API pública.

**Para proyectos existentes: ningún cambio requerido.** Toda la config actual sigue funcionando byte-por-byte igual.

## ¿Qué hay de nuevo?

### Entrenamiento sin holdout (`split.method: "none"`)

El framework ahora permite entrenar un modelo consumiendo **toda la data** sin reservar split de validación ni test. Útil cuando ya tenés métricas de evaluación robustas de corridas previas y querés maximizar la señal del modelo de producción.

```yaml
# config/train.yaml
training:
  split:
    method: "none"          # ← antes: stratified, random, time_series, group_based, stratified_time
```

**Qué cambia bajo el capó:**

| Pieza | Cambio |
|---|---|
| `SplitStep` | Escribe solo `train.parquet`; `val_path` y `test_path` quedan en `None` |
| `TrainingStep` | Acepta `val_path=None`; internamente reserva 10% para early stopping únicamente |
| Métricas | `val_auc` y `val_f1` devuelven `None` honestamente (no números falsos) |
| Contexto | Nuevo campo `holdout_mode`: `"none"` o `"standard"` (autodocumentado) |
| Calibración | Se saltea con un `WARNING` si la activas (necesita val data) |
| Ensemble blending | `use_val_as_oof: true` lanza `ConfigurationError` con 3 alternativas concretas |
| `soft_voting` y K-fold OOF | Funcionan sin val data |
| Director | Auto-skip del step de evaluación con `WARNING` |
| `DefaultEvaluator` | Retorna `skipped=True` defensivamente en vez de crashear |

**Tres alternativas cuando blending pide val:**

1. Proveer un `split.method` con holdout (`stratified`, `time_series`, etc.)
2. Cambiar a `use_val_as_oof: false` (K-fold OOF stacking)
3. Cambiar a `method: "soft_voting"`

## Cambios internos (sin impacto en API pública)

- **ADR-0001 — `GeoFeatures` es ahora el dueño del clustering geográfico.** El KMeans (`geo_cluster`) y la persistencia del `geo_model.pkl` se movieron del ETL (`GeoFeaturesETL`) al transformer (`GeoFeatures`), alineando la implementación con la definición de Transformer en `CONTEXT.md`. `GeoFeaturesETL` queda como un wrapper delgado. `GeoFeatures` expone `fit`/`transform`/`save`/`load` con semántica sklearn pura. Decisión documentada en `docs/adr/0001-geo-features-as-transformer.md`.

```bash

```

No requiere migración de config, modelos guardados, ni runs existentes.

## Próximos pasos sugeridos

1. **Probar en un proyecto real** con `split.method: "none"` después de tener una corrida con holdout que sirva como baseline de calidad.
2. **Comparar el modelo de producción** (full data) contra el último modelo evaluado (con holdout) en una muestra de validación fija — esperá una mejora modesta pero consistente.
3. **Documentar el procedimiento operativo**: cuándo pasar de holdout a no-holdout, cómo versionar el modelo, qué métricas conservar.
